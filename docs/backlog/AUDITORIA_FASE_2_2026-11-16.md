## C. Se corrige antes del commit

Cada punto se cierra con un test que falle sin el arreglo y `make check` en verde. Marcar la casilla al cerrarlo.

- [x] **C1 Una fuente vacía borra la colección** — `app/services/sincronizacion.py`, cálculo de `ausentes`: si el
  conector devuelve 0 registros (respuesta 200 con `{}` o secciones vacías), se borran todos los documentos
  sincronizados. Con 0 registros y documentos existentes, es `ErrorConector`; vaciar exige un parámetro explícito.
- [x] **C2 Dos elementos con el mismo nombre se pisan** — `app/conectores/resume.py`, `_identificador`: dos cargos en
  la misma empresa generan el mismo `id_externo`; el segundo se cuenta como «sin cambios» y nunca se indexa.
  Desambiguar el id o detectar ids repetidos y lanzar `ErrorConector`. Además el resumen dice RECHAZADO y el trabajo
  dice DUPLICADO para el mismo caso: una sola clasificación.
- [x] **C3 Trabajo colgado si el worker muere** — `app/worker.py`: con `max_tries = 1`, un reinicio a mitad de un
  archivo deja el trabajo «en curso» para siempre y su copia en disco. Guardar inicio del trabajo y barrer los
  vencidos hacia error con motivo (y borrar su carpeta), o la alternativa que midas que funciona con arq real.
  Corregir el comentario de cabecera del archivo.
- [x] **C4 Excepciones que no suman al contador** — `app/worker.py`, `procesar_archivo`: solo se captura `AppError`.
  Un `FileNotFoundError` al leer la copia, un 404 del trabajo o un error de base dejan el archivo sin contar y el
  trabajo sin terminar. Toda excepción se registra (`logger.exception`) y cuenta como ERROR.
- [x] **C5 Lote sin tope real de tamaño** — `app/routers/trabajos.py`, `_guardar_copias`: con
  `Transfer-Encoding: chunked` no hay `Content-Length` y se copia a disco sin límite. Contar bytes al copiar (tope por
  archivo y tope del lote) y corregir el docstring de `app/common/limite_cuerpo.py`, que afirma una segunda barrera
  que en lotes no existe.
- [x] **C6 Trabajo «pendiente» eterno si falla el guardado** — `app/routers/trabajos.py`: el trabajo se crea antes
  de copiar los archivos y solo se limpia si falla la cola. Cualquier fallo desde la creación descarta el trabajo y
  su carpeta. Comprobar que la cola responde antes de copiar.
- [x] **C7 El worker lee y borra la ruta que le llega por Redis sin validarla** — `app/worker.py`: comprobar que la
  ruta está bajo `settings.INGESTA_TEMPORAL` antes de leerla o borrarla, y comprobar el tamaño con `stat` antes de
  `read_bytes()` (hoy un archivo de 1 GB entra entero en la memoria del worker).
- [x] **C8 «Terminado» antes de terminar** — `app/models/trabajo.py` y `app/worker.py`: en una sincronización el
  estado pasa a terminado al procesar el último registro, antes de borrar los ausentes y de contarlos. El total
  incluye las bajas, o se fija al final.
- [x] **C9 Documento y contador en transacciones distintas** — `app/services/ingesta.py` y `app/worker.py`: un corte
  entre los dos commits deja el documento guardado y el trabajo sin contarlo. Mismo commit, o documentarlo como
  límite conocido y cubrirlo con el barrido de C3.
- [x] **C10 Visión sin timeout** — `app/providers/vision.py`: `ChatOllama` se crea sin timeout aunque existe
  `TIMEOUT_LLM_SEGUNDOS`. Con un Ollama colgado, la página espera la hora entera del trabajo.
- [x] **C11 Redis pierde la cola al recrearse** — `docker-compose.yml`: sin volumen ni AOF. Persistirla, o dejarlo
  escrito como aceptado porque C3 limpia los trabajos huérfanos.
- [x] **C12 Constantes del worker fuera de su sitio** — `app/worker.py` y `app/routers/trabajos.py`: los nombres de
  función de arq van en `app/config/constantes.py`; el router no debe importar `app.worker` (hoy arrastra todo el
  worker y lee la configuración de Redis al importar). Registrar las dos funciones con nombre explícito.
- [x] **C13 Restos** — comentarios «commands auto generated by Alembic - please adjust!» en las migraciones nuevas;
  `python-dotenv` sigue en `pyproject.toml` y ya no se usa; helpers de tests sin tipo de retorno.

## D. Abierto, no bloquea este commit

- **D1 El candado de Docling es por proceso.** Con 2 procesos de la API y 1 worker pueden correr tres conversiones a
  la vez, y cada subida síncrona ocupa un hilo durante minutos. → FASE_4 (antes de exponer): mandar toda subida
  pesada por la cola.
- **D2 Re-embed** — mientras corre, los documentos con el modelo viejo desaparecen de la búsqueda sin aviso; una
  excepción en un documento aborta la corrida entera; `--retrocear` rehace todo al reintentar.
- **D3 `/trabajos` no informa páginas en blanco ni sin indexar**: solo se registran en el log, así que el criterio
  «páginas sin texto buscables» no se puede comprobar por la API.
- **D4 `httpx.Client` del conector nunca se cierra.**
- **D5 Tests que faltan o que no pueden fallar** — el de `--retrocear` compara antes y después con el mismo
  troceador y pasaría aunque no hiciera nada; el del límite de lotes solo lee la configuración.
- **D6 Redis sin contraseña** (publicado solo en 127.0.0.1). → FASE_4.
